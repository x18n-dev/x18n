x18n needs Node.js 22 or later. Run the commands in this page in the root directory of your project.

## Try it without a config

x18n works without a config file. It reads i18n-ally settings when the project has them, detects the i18n library from `package.json` (including the workspace packages of a monorepo), and looks for locale files in directories such as `locales`, `i18n`, `lang` or `messages`.

1. Show what x18n found:

   ```sh
   npx @x18n/cli
   ```

   The output lists the locales with their coverage, and the counts of resources, keys and usages.

2. Check the project:

   ```sh
   npx @x18n/cli check
   ```

`x18n check` prints each problem with its file, line and column, like `tsc`:

```
src/App.vue:17:15 - error missing-key: "app.titel" is not defined in en.
17     <p>{{ $t('app.titel') }}</p>
                 ~~~~~~~~~

src/locales/de.json:4:6 - error placeholder-mismatch: "app.greeting" in de has different placeholders than en: missing name.
4     "greeting": "Hallo"
       ~~~~~~~~

src/locales/en.json:18:4 - warning unused-key: "unused" is not used.
18   "unused": "Nobody uses me",
      ~~~~~~

Found 2 errors and 1 warning in 3 files.
```

The command exits with code 1 when it finds errors. Warnings do not fail it. See [Checks](/checks) for every check.

If x18n finds the wrong files, or none, run `npx @x18n/cli doctor`. It shows the detected presets, the resources that each locale finder found, and the source files that each scanner read.

## Install

Add `x18n` to the dev dependencies of the project:

::code-group

```sh [pnpm]
pnpm add -D @x18n/cli
```

```sh [npm]
npm install -D @x18n/cli
```

```sh [yarn]
yarn add -D @x18n/cli
```

::

The TS config imports `defineConfig` from `x18n`, so the package must be installed in the project before you write an `x18n.config.ts`.

## Write a config

`x18n init` detects the setup and writes `x18n.config.ts`:

```sh
npx @x18n/cli init
```

```ts [x18n.config.ts]
import { defineConfig } from '@x18n/core'

// Detected presets: vue-i18n. They apply automatically.
export default defineConfig({
  sourceLocale: 'en',
  resources: [
    {
      pattern: 'src/locales/{locale}.{ext}',
    },
  ],
})
```

A project that has no `package.json`, such as a PHP or Ruby project, can use YAML or JSON instead. These files need no installed package:

```sh
npx @x18n/cli init --format yml
```

`x18n init` refuses to replace an existing config. Pass `--force` to replace it. See [Configuration](/guide/configuration) for every way to change the setup.

## Run the check in CI

Add a script to `package.json`:

```json [package.json]
{
  "scripts": {
    "i18n:check": "x18n check"
  }
}
```

Then run `pnpm i18n:check` (or `npm run i18n:check`) in your CI. [CI](/surfaces/ci) shows a GitHub Actions workflow that puts the problems on the lines of a pull request.
