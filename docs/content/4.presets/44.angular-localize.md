---

The `angular-localize` preset supports [Angular's built-in i18n](https://angular.dev/guide/i18n) with `@angular/localize`.

## Detection

The preset applies when the project depends on `@angular/localize` and `angular.json` has an `i18n` block. Libraries such as ng-bootstrap depend on `@angular/localize` without translating anything, so the dependency alone is not enough.

```ts [x18n.config.ts]
import { defineConfig } from '@x18n/core'

export default defineConfig({
  presets: ['angular-localize'],
})
```

## Locale files

The preset reads the `i18n` block of every project in `angular.json`:

- `sourceLocale`, as a string or as `{ "code": "..." }`, is the source locale. Angular's default is `en-US`.
- Each entry of `locales` is a translation file, as a path, a list of paths or `{ "translation": ... }`.
- The source file comes from the `extract-i18n` target: `outputPath` and `outFile`, with `messages.json` by default.

```json [angular.json]
{
  "projects": {
    "app": {
      "i18n": {
        "sourceLocale": "en-GB",
        "locales": {
          "tr": "src/locale/messages.tr.json"
        }
      },
      "architect": {
        "extract-i18n": {
          "options": { "format": "json", "outputPath": "src/locale" }
        }
      }
    }
  }
}
```

Only the JSON format (`--format json`) is supported. XLIFF, XMB and ARB files are not read yet.

A JSON file holds `{ "locale": "tr", "translations": { "home.title": "..." } }`. The preset reads the `translations` object, and edits go back into it. Keys are flat: the ID `home.title` is one key, not a nested path.

## Supported syntax

Only custom IDs are read. Angular generates an ID from the text and meaning when a message has no custom ID, and the preset does not compute it.

In templates, the `i18n` attribute and `i18n-*` attributes with an ID after `@@`, including a meaning and description before it:

<!-- eslint-skip -->

```html [src/app/home.html]
<h1 i18n="@@home.title">Hello</h1>
<a title="Blog" i18n-title="site menu|Blog link@@nav.blog">Blog</a>
```

In TS and JS files, `$localize` tagged templates with an ID:

```ts [src/app/app.routes.ts]
const title = $localize`:@@title.projects:Projects`
```

These usages are `home.title`, `nav.blog` and `title.projects`.

## Placeholders

Angular placeholders: `{$INTERPOLATION}`, `{$START_LINK}`, `{$CLOSE_LINK}`.
